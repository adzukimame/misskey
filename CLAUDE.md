This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

This repository is a fork of Misskey, a decentralized ActivityPub social platform, maintained at `adzukimame/misskey`. The main branch is `develop-mame`. Many upstream features have been removed in this fork (for example widgets, server-info/serverStats, and the bundled sensitivity-detection model), so don't assume an upstream feature exists here. CHANGELOG entries, PR descriptions (`.github/pull_request_template.md`: What / Why / Additional info) and commit messages are written in Japanese.

This is a pnpm workspace (`pnpm@9`, Node version in `.node-version`). It has four packages:
- `packages/backend`: a NestJS + TypeORM (PostgreSQL) + Redis/BullMQ server. It is compiled with SWC.
- `packages/frontend`: a Vue 3 + Vite SPA.
- `packages/sw`: the service worker, built with esbuild.
- `packages/misskey-js`: the TypeScript API client and type SDK. Its `generator/` subpackage is `misskey-js-type-generator`.

## Commands

Setup: copy `.config/example.yml` to `.config/default.yml`, then run `pnpm install`.

- Full build: `pnpm build`. This runs `build-pre` (which writes `built/meta.json`), then builds every package, then runs `build-assets` (which also generates `locales/index.d.ts`).
- Dev mode: `pnpm dev`. This cleans, pre-builds, builds misskey-js, then watches the backend (SWC) and frontend (Vite HMR). Set `MK_DEV_PREFER=backend` to use `vite` watch instead.
- DB migrations: `pnpm migrate` and `pnpm revert` (TypeORM, `packages/backend/ormconfig.js`). Migration files are plain JS in `packages/backend/migration/`, named `<timestamp>-<Name>.js`.
- Lint everything: `pnpm lint`. Each package's `lint` runs `typecheck` and then `eslint`. To lint one package, use for example `pnpm --filter backend lint` or `pnpm --filter frontend typecheck`.

### Tests
Backend tests need Postgres on port 54312 and Redis on port 56312:
```
docker compose -f packages/backend/test/compose.yml up -d
cp .github/misskey/test.yml .config/test.yml
pnpm build-pre && pnpm --filter misskey-js build
```
- Backend unit tests (`test/unit/**`, `src/**/*.test.ts`): `pnpm --filter backend test`
- Single backend test file: `cd packages/backend && pnpm jest -- test/unit/RoleService.ts` (you can add `-t "name"` to filter by test name)
- Backend e2e tests (`test/e2e/**`, against a built server): `pnpm --filter backend test:e2e`. To skip the rebuild, use `pnpm jest:e2e -- test/e2e/note.ts`.
- Frontend tests (Vitest): `pnpm --filter frontend test`
- misskey-js tests (Jest + tsd): `pnpm --filter misskey-js test`
- Cypress: `pnpm e2e`

## Architecture notes

### Backend (NestJS DI)
- Entry point: `src/boot/entry.ts`. The module tree is `MainModule` → `GlobalModule` (config, DB, Redis via the symbols in `src/di-symbols.ts`) → `CoreModule` / `ServerModule` / `QueueModule` / `RepositoryModule`.
- `src/models/`: TypeORM entities, plus `RepositoryModule` and `json-schema/` (the response schemas that endpoints reference with `ref`).
- `src/core/`: domain services (`*Service.ts`), `entities/*EntityService.ts` (which pack DB rows into API objects), `activitypub/` (federation) and `chart/`.
- `src/queue/`: BullMQ job processors.
- `src/server/`: Fastify servers for the API, ActivityPub, web/SSR, files, nodeinfo and well-known.
- **API endpoints** live in `src/server/api/endpoints/**`. Each file exports `meta` (tags, credential and permission requirements, `res` schema, `errors` with unique UUID ids) and `paramDef` (a JSON schema), plus a default `@Injectable()` class that extends `Endpoint`. When you add or remove an endpoint, you must update **both** `src/server/api/endpoints.ts` and `src/server/api/EndpointsModule.ts`.
- Imports use the `@/` alias for `src/` and need explicit `.js` extensions (ESM).

### misskey-js autogen
`packages/misskey-js/src/autogen/` is generated from the backend endpoint schemas. CI (`check-misskey-js-autogen.yml`) fails if it's stale. After changing any endpoint's `meta`/`paramDef` or a model json-schema, regenerate it:
```
pnpm build-misskey-js-with-types
```
The root `package.json` version and the `packages/misskey-js/package.json` version must be identical; CI checks this.

### Frontend
The frontend code is organized into `src/pages/` (route pages; the route table is `src/router/definition.ts`), `src/components/` (`Mk*` components), `src/ui/` (layout shells) and `src/scripts/` (helpers). Global state lives in `store.ts` (pizzax), API calls go through `scripts/misskey-api.ts` and `os.ts`, and streaming is in `stream.ts`. Strings come from `i18n.ts`.

### Locales
Only edit `locales/ja-JP.yml`. The other locale files are synced from translations and must not be edited by hand. `locales/index.d.ts` is generated by `build-assets`. CI runs `cd locales && node verify.js`.

### Changelog
User-visible changes go under `## Unreleased` in `CHANGELOG.md`, grouped as General / Client / Server, using `Feat:`/`Enhance:`/`Fix:` prefixes and written in Japanese. Changes cherry-picked from other forks note their source.
